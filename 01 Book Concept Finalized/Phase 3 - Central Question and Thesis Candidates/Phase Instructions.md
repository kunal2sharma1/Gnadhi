# Phase 3 — Central Question and Thesis Candidates

## Objective
Develop one strong central question and a provisional working thesis without pretending the thesis has already been historically proven.

## What this phase must accomplish
Turn the clarified concept and definitions into precise questions and competing thesis formulations. The goal is to make the book intellectually testable.

## Sub-phases

### Sub-phase 3.1 — Central Question Development
**Assigned to:** ChatGPT Go execution account

**Work:** Read the approved Phase 1 and Phase 2 context package. Develop several possible central questions. The question must express the real intellectual problem without assuming the desired answer.

**Output:** `03.1 Central Questions.md`

### Sub-phase 3.2 — Thesis Candidate Development
**Assigned to:** ChatGPT Go execution account

**Work:** Develop several thesis candidates: strongest version, cautious version, evidence-first version, and any better formulation discovered during analysis. For every candidate, list its assumptions and the evidence that would be required to support it.

**Output:** `03.2 Thesis Candidates.md`

### Sub-phase 3.3 — Independent Thesis Stress Review
**Assigned to:** ChatGPT Go execution account — Critical Review role

**Work:** Read the complete supplied context and challenge every thesis candidate. Look for overstatement, unsupported causation, ideological conflation, false certainty, weak definitions, and alternative explanations. State exactly what evidence could disprove or substantially change each candidate.

**Output:** `03.3 Thesis Stress Review.md`

### Sub-phase 3.4 — Working Thesis Selection
**Assigned to:** This ChatGPT account — Product Manager

**Work:** Review the candidate theses and stress review. Select or rewrite one provisional working thesis and one central question. Record why it was selected and what remains unproven.

**Output:** `03.4 Working Thesis.md`

## Execution rule for all sub-phases
Each execution assignment must include a self-contained context pack, exact task, expected Markdown sections, and completion condition. The agent must not be expected to reconstruct the project from memory.

## Handoff rule
Every thesis-related output must distinguish between project decisions and historical propositions. Strong wording is not evidence.

## Completion condition
There is one provisional working thesis, one central question, a list of assumptions, and a clear list of evidence requirements for later research.

## Next phase dependency
Phase 4 must try to break the current working concept and thesis using the complete approved context from Phases 1–3.
